# ADR-0004: 历史数据不可变性

**日期：** 2026-07-26
**状态：** 已接受
**关联 Issue：** #117, #118

## 背景

2026-07-26 架构审查后重构 `pushplus.py` 时，发现 2024-07-24 的 FGI 值从 39.26 变为 41.82（+2.57）。根因分析：

1. 对比 GitHub Actions 产物（`fgi-results-2026-07-24`）与本地数据库
2. 发现 F1（融资余额占比）原始数据变化：
   - `f1_margin_ratio`: 0.0308 → 0.0194（-37%）
   - `f1_market_cap`: 457,333 → 726,942（+59%）
   - `f1_percentile`: 0.3368 → 0.7220（+114%）
3. 其他 11 个指标完全一致，无变化
4. 根因：akshare 上游 API 对历史融资融券数据做了修正

**核心问题**：当前设计中 `daily_run` 每次运行会覆盖 `raw_data` 表中所有指标的原始数据，导致历史 FGI 值随上游数据源变化而变化。

## 决策

**接受历史数据可变性，不改为不可变。**

理由：
1. **数据准确性优先**：如果上游 API 修正了历史数据，我们希望使用修正后的数据，而非锁定旧数据
2. **实现复杂度低**：每次覆盖是最简单的实现，不需要 "已存在则跳过" 的条件判断
3. **影响范围有限**：FGI 是每日快照，历史值变化不影响当日推送的正确性
4. **用户可追溯**：GitHub Actions 产物保留了每次运行的数据库快照，可追溯历史变化

## 约束

1. **每日推送的 FGI 值是"最终值"**：一旦推送，即使后续重跑历史数据导致值变化，已推送的值不变
2. **GitHub Actions 产物是唯一的历史快照**：`fgi-results-YYYY-MM-DD` 产物保留了每次运行的完整数据库
3. **Web 前端显示的是当前数据库中的值**：如果重跑历史数据，前端显示的值会变化

## 后果

- ✅ 上游数据修正会自动反映在历史 FGI 中
- ✅ 实现简单，无额外逻辑
- ❌ 历史 FGI 值不可靠（依赖上游数据源的稳定性）
- ❌ 需要告知用户：历史值可能随时间变化
