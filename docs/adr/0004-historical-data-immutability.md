# ADR-0004: 数据源口径变更时必须回填历史数据

**日期：** 2026-07-26
**状态：** 已接受
**关联 Issue：** #117, #118

## 背景

2026-07-26 架构审查后发现 2024-07-24 的 FGI 值从 39.26 变为 41.82（+2.57）。根因分析：

1. 对比 GitHub Actions 产物（`fgi-results-2026-07-24`）与本地数据库
2. 发现 F1（融资余额占比）原始数据变化：
   - `f1_market_cap`: 457,333 → 726,942（+59%）
   - `f1_margin_ratio`: 0.0308 → 0.0194（-37%）
   - `f1_percentile`: 0.3368 → 0.7220（+114%）
3. 其他 11 个指标完全一致，无变化

**根因：不是上游 API 修正数据，而是代码改了口径。** V3.8 的 `fetch_market_cap` 只取上海市价总值，V3.8.3 改为沪+深合计（与分子融资余额的沪深合计口径对齐），但没有回填历史 raw_data。旧数据库存着上海-only 口径的旧值，新运行用沪深合计口径写入新值——所以同一日期的值"变了"。

## 决策

**数据源口径变更时，必须同步回填历史 raw_data，不允许新旧口径混合。**

理由：
1. **数据准确性优先**：历史 FGI 值必须反映当前代码的正确口径，不能混入旧口径数据
2. **混合口径比缺失更危险**：旧值和新值用不同计算方式产生，混在一起导致时间序列不连续，百分位计算失真
3. **回填成本可控**：大多数指标的 raw_data 可从 API 重新获取或从其他字段重算
4. **审计一致性**：12 指标系统审计（2026-07-26）确认所有指标口径一致，不存在同类问题

## 约束

1. **每次修改数据源计算逻辑时，评估是否需要回填**：如果改了口径（如分母、字段、单位），必须同步回填历史数据
2. **回填优先于新增功能**：数据准确性问题发现后，应优先修复再继续新开发
3. **GitHub Actions 产物保留原始快照**：`fgi-results-YYYY-MM-DD` 产物保留了每次运行的完整数据库，可追溯回填前后的差异

## 后果

- ✅ 历史 FGI 值始终反映当前代码的正确口径
- ✅ 时间序列连续，百分位计算可信
- ✅ 12 指标审计可作为数据质量基线
- ❌ 口径变更时需要额外的回填工作
- ❌ 回填可能需要网络请求（API 数据获取），增加一次性运维成本
